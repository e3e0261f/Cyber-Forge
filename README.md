Esc / q / Q：无条件优雅退出并清理终端还原。
A / a：招募学徒（实时扣除阶梯动态递增费用 200 + count^2 * 300）。
B / b：扩容背包（+2 槽位，消耗 500 💰）。
S / s：安全一键上架藏宝阁（清空全废品，强制锁定保护史诗/传说/神话装备）。
任意击键 / 打字：手动捶打原铁（+1 锤击，注入键盘时间差熵因子）。
三、 技术架构与并发契约 (Technical Standards)
Tokio + Crossterm 异步事件流 (EventStream Async Pipeline)：
输入监听必须使用 crossterm::event::EventStream + tokio::select!，严禁使用同步阻塞的 crossterm::event::poll()。
严禁在 Linux/SSH 终端下过滤 KeyEventKind::Press，以保证多平台按键 100% 捕获。
并发安全与渲染剥离 (Lock-Free Render)：
状态管理必须统一使用 SharedGameState(Arc<RwLock<GameState>>)。
渲染剥离原则：必须在 terminal.draw 外部完成异步读取（state.read().await），绝不允许在 terminal.draw 闭包内部做阻塞等待。
数据溢出防护 (Number Safety)：
所有金币/价格显示必须走 format_compact_number，支持 K/M/B/T/Qa 自动压缩，防止突破列宽。
四、 版本增量更新准则 (Update Rules)
继承式递进 (Additive Only)：后续版本（v1.9.7、v2.0...）更新必须在现有 4 个 Panel 和对应 Rust 模块（numbers.rs, titles.rs, sword_gen.rs, state.rs, ui/*）基础上进行功能叠加，严禁覆盖、删减既有核心模块或重写底层 TUI 框架。
交付即编译：每次版本输出必须保证代码间类型定义无缝对接，提供完整可编译运行的代码清单。
我们将此公约作为项目的标准基线。后续所有功能拓展（如：防篡改本地存档、Steaming 市场挂单、五行相克计算等）均将在此框架下平滑增量构建！
